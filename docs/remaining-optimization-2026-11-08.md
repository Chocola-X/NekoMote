## 1. 结论与取舍

| 候选 | 核查结果 | 本轮处理 |
| --- | --- | --- |
| 音频空闲/暂停轮询 | `Device::Impl::run()` 即使没有播放也固定 sleep 12ms；暂停 stream 仍 sleep 4ms。真实私有 Pulse 服务下可重复产生无业务工作的周期切换 | 保留事件等待；低成本、收益稳定 |
| GL/GLES UI 上传与绘制 | `draw_text()` 为完全被 scissor 裁掉的文字仍上传两个 buffer 并 draw。实际 vanilla 有 37 项，菜单限高后问题更突出 | 保留文字剔除；不重构整个合批协议 |
| GLES atlas 二次幂填充 | 三模型的 RGBA 纹理容量有约 7.36～31.51 MiB 理论差额；直接使用 NPOT 存储仍破坏既有画面 | 实测失败后恢复原代码，未保留 |
| 全部语音按需解码 | 本地 195 bank 的 PCM 最小/中位/最大仅 3.70/5.78/6.29 MiB；需增加首播异步解码、缓存和失败交接 | 有潜力，但收益与复杂度不占优，暂不实施 |
| 普通 Over 直绘/延迟 color target | 195/195 初态需要颜色保护，4 个还用 Multiply；现有直绘筛选条件也有半透明反例 | 未找到实际可用收益，不改语义或目标分配 |
| Vulkan 合并上传/子分配 | 逐图同步、独立分配属实，但本地每模型图集很少；仅影响加载，尚无瓶颈证据 | 不引入分配器或新上传状态机 |
| geometry 重复编译、revision、暂停呈现、alpha 校验 | 已由前一轮处理 | 本轮不重复实施 |

这里的优先级按实际资产和可验收成本排序，不沿用原报告的 P1/P2 标签作为收益证明。

## 2. 音频：保留的优化

主循环在 Ready 或 paused 状态调用阻塞式 `pa_mainloop_iterate`；
`submit()` 发布命令后使用 Pulse 的 `pa_mainloop_wakeup()` 唤醒，析构同样唤醒后 join。
mainloop 由 RAII 持有，在 worker 发布前创建，在 join 后释放；失败退出后 endpoint 也不会悬空。
连接阶段仍保留轮询及 5 秒 deadline；正在播放时仍使用原来的 4ms 节奏。
未修改 PCM/bank 所有权、预解码策略、200ms 播放缓冲、RMS 时钟或设备重试语义。

同一私有 null sink，串行交替执行旧/新二进制三轮，每轮先稳定 200ms，
Ready/Paused 各测 3 秒，Playing 测 1 秒。以下为三轮范围：

| 指标 | 基线 | 修改后 |
| --- | --- | --- |
| Ready worker 上下文切换/秒 | 82.994～82.996 | 0 |
| Paused worker 上下文切换/秒 | 246.315～246.322 | 2.666～2.667 |
| Playing worker 上下文切换/秒 | 244.928～247.971 | 244.951～245.967 |
| Play 命令至 Playing 状态 P50 | 约 12.10～12.12ms | 约 0.256～0.261ms |
| Ready 析构 join | 约 11.98～12.01ms | 约 0.109～0.273ms |

切换计数来自该 worker 的 `/proc/self/task/<tid>/status`，是周期唤醒的近似观测，
不等于硬件功耗。CPU tick 分辨率为 10ms，短样本大多为零，不能据此报告 CPU 百分比。
命令延迟由 200µs 轮询观测状态，不是声音到达扬声器的延迟。
服务自带的暂停 stream timing 事件仍会唤醒，因此不追求暂停绝对零事件。

新增显式 opt-in 集成用例覆盖真实连接、非零 RMS、暂停跨越 RMS 分段后的时钟保持、
恢复、自然结束、20 次 Play/Stop、暂停时 Play，以及 Ready/Paused 析构和 bank 引用释放。
默认不连接用户声音服务，缺少私有测试服务时明确 Skipped。
另以有效 bank 检查服务断连、5 秒无响应连接 deadline、失败后拒绝命令和析构；
ASan/UBSan 执行实际播放流程未报告问题。未做 TSan、真实扬声器延迟、长期或多设备认证。

## 3. UI：接受局部轻微代价，保留文字剔除

只在字形矩形完全落在实际整数 scissor 外时跳过 `glBufferData` 和 draw；
仍调用原有字形生成，使用真实字形顶点边界，保留部分可见文字及其 overhang。
正文原点在裁剪区内时不扫描边界；原点在外时才扫描。
不假定逻辑行高等于字形边界，也不改变 layout、hit-test、裁剪规则或透明顺序。
裁剪状态在 push/pop、reset 和帧边界失效，未新增常态堆分配。

800×1080、同一字体和本地 8 组目录，最长 vanilla 37 项：

| 菜单场景 | draw/帧（旧→新） | buffer 上传/帧 | 上传字节/帧 |
| --- | --- | --- | --- |
| 长列表顶部 | 78 → 51 | 133 → 79 | 81,504 → 35,808 |
| 长列表底部 | 78 → 53 | 133 → 83 | 81,504 → 45,888 |
| 仅图标、全部分组收起 | 不变 | 不变 | 不变 |

UI 局部微基准中长列表 CPU 耗时约下降 30%，但 desktop GL 的收起菜单
三轮平均耗时增加约 14～25µs。最初按“任何回退都撤回”标准撤回了候选；
用户更新标准后补测完整链路再决定保留。
试过的通用矩形/图标/箭头剔除没有保留，最终改动仅涉及文字。

完整帧对照包含 wintermaid 会话 advance/prepare、真实模型 GL prepare/render 和 UI；
固定 1/60 秒输入，同一个程序、设备和线程，两套独立但同初态的会话交替先后顺序，
每场景预热 100 对，采样 120 对，60Hz 调度，重复三轮（未绑核）。

## 4. GLES NPOT：撤回

在同一 NVIDIA GLES 上，用不填充的纹理尺寸替换 POT 存储，其余 shader、过滤和 UV 不变。
三模型 × 0/60/180 tick × 原始缩放/分数缩放与翻转/alpha=.6，共 27 对画面。
全部出现像素差异；导出 straight RGBA 的低 alpha 像素最大误差为 255/255，
限制两张图 alpha 都至少为 16/255 后，仍有 6～16/255 的最大误差。
因此不能把问题归为无可见贡献的透明 RGB。停止性能试验，完整恢复原纹理分配代码。
显存差额只记录为 RGBA 容量估算，不宣称实际已回收显存。
