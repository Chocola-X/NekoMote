# 第二份性能报告的复核与实测

起点 `a91f75e`，输入 `experiments/nekomote_performance_optimization_report.md`。
纹理压缩按用户要求跳过，继续保持 x86-64 v1、GL 3.3 / GLES 3.0 和 Vulkan 1.0 基线。
历史回退不重新实现，结论以实际代码、同条件性能和前后像素对照为准。

| 报告建议 | 复核 |
| --- | --- |
| 双三次张量分离、取消 `noinline` | 跳过。[曲面重排](optimization-lessons.md#曲面重排与降精度不能用代数等价替代输出验证)会改变浮点累加和 UV 保存点；嵌套或旋转后不能假设行列共享。取消局部调用边界也有 LTO 回退记录。精确的网格比例复用已由 `a91f75e` 交付，报告的合成吞吐不能换算为真实整帧加速。 |
| 高刷脏帧、音频等待、D-Bus 降频 | `ef47367`、`df9a9c0` 已处理 Qt 提交节奏和指针绕过限帧，现有帧缓存也已跳过未变内容的上传。作者步不等价于 UI、输入或宿主输出变化，不能用它取代宿主重绘判定；Qt basic 循环额外提交仍单独记录。Pulse 空闲已事件化，失联重试见 `c129e04`；X11 的总线访问已限频，进一步移出帧循环有回退记录。 |
| 参数脏传播、排序缓存 | 关键帧有区间游标，物理锚点已有依赖闭包。报告未证明保持组合、遮罩、资源分支及失败事务所需的缓存成本能换回收益。没有放宽已有求值和排序规则。 |
| 全屏裁剪、GLES 去补齐、背景走直通 | 前两项已因性能或精度退出；背景帧本来就是 `PremultipliedOver`，不经过角色的离屏色彩合成。 |
| R8 遮罩、RGBA 打包 | 当前遮罩是五位绿通道的 16-bit packed 格式，尺寸向下取二次幂。R8 会改变逐次 alpha 混合的量化；RGBA8 多通道打包也不能直接继承当前量化、插值和遮罩坐标规则。跳过报告中的估算及改法。 |
| Vulkan 着色器特化 | 五个角色管线把写遮罩、保护和预乘改为特化常量，保留动态遮罩采样和混合契约。18 对最终 PNG 相同，但到 GPU 完成的均值/P50/P95 分别上升 **4.52% / 2.02% / 6.02%**，撤回。现有管线没有深度遮挡，不能用 Early-Z 假定它好转。 |
| 相邻绘制合批 | 只试相邻、图集相同、索引连续、无保护、无遮罩的普通 Over，保持绘制顺序。GL 和 Vulkan 各 18 对 PNG 一致；GL 完成 P50 −0.25%，Vulkan +0.76%，未见足够整体收益，撤回。 |
| Vulkan UI 小缓冲 | 初始化实际上按 65,536 个顶点预留，不是平时按 1 MiB 下限动态分配。直接缩小会把设备分配移到首次开面板等绘制路径；本轮没有数据支持这个取舍。 |
| 音频即时解码、模型堆回收 | 长语音假设不成立；上轮按实际素材计量，声库最大约 6.29 MiB。不能直接在交互求值时读盘解码；需另测触发延迟、RMS 与失败体验。全局 `malloc_trim` 已做过归因，作用到整个 Qt 宿主，跳过。未引入 JSON 分配器或改变资产 schema。 |

## 背景切换：复用已上传的旧图片

旧实现为每次渐变新建候选渲染器，并重新解码、上传旧背景。继续使用候选事务：
新 peer 引用同一后端族中的不可变旧设备图片，独立拥有本地纹理 ID、几何和绑定；
Vulkan 为本地描述符池一次分配两套绑定。新图上传成功后才替换当前 renderer。
准备失败时旧 renderer 及其资源不动；旧源退出后，引用随最后一个使用者退出而释放。
无全局缓存、不跨上下文或设备，未改变背景的取景、过渡曲线、播放时钟或构图状态。

对照是高层壁纸 ABI，而非模拟解码计时。使用真实 `BG_07A`、`BG_13A`、`BG_24A`、
`BG_48C` PNG（均 1920×1080），`chocola/date-a`、固定种子、静音、0.5 s 渐变，
960×540 隐藏输出。每次 8 次预热，32 次切换，基线与候选三轮交错；
采样包住 `advance(0)` 的候选准备，独立等待才画图。GPU 截图对照另跑，
没有把读回或截图编码计入切换耗时。

| 后端 | 切换耗时 P50 | 切换耗时 P95 | 切换线程 CPU P50 |
| --- | ---: | ---: | ---: |
| Debian 12 / i5-2410M / HD 3000，Mesa 22.3.6 GL 3.3 | 144.27 → 75.64 ms | 145.43 → 76.81 ms | 144.26 → 75.63 ms |
| 本机 Xeon E5-1680 v4 / RTX 3080 Ti，NVIDIA 580.82.09 Vulkan | 123.78 → 62.73 ms | 142.06 → 67.26 ms | 119.82 → 60.52 ms |

Release/O3/LTO：低端机二进制用 Debian 12 GCC 12.2，Vulkan 用本机 GCC 15.2。
GL 每轮计到 64 → 32 次大纹理上传。少一次旧图解码和 GPU 副本是可验证的资源变化；
进程 RSS 高水位受驱动和其他资源影响并未稳定下降，没有据此报告整机内存或显存降幅。
收益发生在背景切换，不外推到既有背景的每帧运行。

GL 和 Vulkan 各 8 对 PNG 逐字节一致，覆盖初态、渐变起步/中段、未结束时再次切换、
结尾、清除和清除后恢复。低端机通过 GL loader 对新图上传注入错误，失败前后 PNG 一致，
当前背景 ID 未变；断开隔离目录中的旧 PNG 链接后，重试仍从旧纹理正确渐变。
GL/GLES/Vulkan 回归覆盖不同 renderer 族拒绝、缺失 ID、重复 ID、源 renderer 先销毁、
逐步淡化和释放描述符；另有三组 ABI 检查通过。Debian 播放器 ELF 标记 `x86-64-baseline`。
无全桌面安装、外部资产改写或长期功耗结论。

## 两项稳态试验的测量范围

GPU 着色器和合批试验都用 1280×720、3 个模型 × 待机和固定拖动，每场 120 帧预热、
600 帧 × 三轮交错。GL 合批在低端机 HD 3000，Vulkan 两项用本机 RTX 3080 Ti。
独立计数中，七个型号的渲染命令理论上可少 38%–49%（允许相同遮罩及混合的上限，
实际试验条件更窄）。低端机合批到 CPU 提交的 P50 仅下降 0.26%，P95 增加 0.23%；
Vulkan 完成 P50 分组变化为 −9.01% 至 +5.49%。没有把减少命令数折算成 GPU 收益。
到完成时间含 fence 等待，不等同 GPU 独立时间戳。

证据及被撤回的候选保存在 `experiments/performance-followup-2026-11-18/{evidence,work}/`。
