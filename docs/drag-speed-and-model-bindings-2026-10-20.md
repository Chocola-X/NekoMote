# 拖拽速度、长发与裙摆响应

交互驱动策略已由 [800 px/s 修正](drag-800-response-2026-10-20.md) 取代；本文保留当期调查与验证记录。

2026-10-20，基线 `38ceb0d`；Codex / GPT-6（精确变体未暴露）。
用户先要求核查长发、裙装响应差异，随后指定 Chocola / Vanilla wintermaid，
并要求慢拖轻、快拖强、两者之间连续过渡。此变更据此调整交互输入策略。

## 核查结论

扫描本地 195 型号、1170 条链。当前资产的链长均为 64/48，横向输出倍率均为
0.75/0.25，伸长系数也相同；摩擦、重力、bend 和实际制作的几何关键帧存在差异。
不能将外观长发理解为自动采用更长的物理链。

Chocola / Vanilla 的 wintermaid、wintermaid-b 均完整绑定：

- `center_rearhair` → `hair_LR / hair_UD / hair_LR_M` → 两件活动的
  `■髪揺れ_後髪`，即双马尾。
- `center_obj` → `quake_LR / quake_UD / quake_LR_M` → 裙摆及部分饰物。
- Chocola/wintermaid-b 另有右侧发，Vanilla/wintermaid-b 另有左侧发；
  它们与双马尾是不同绑定，实际使用的锚点均存在。

逐项强制参数 ±30 时，双马尾产生明确几何变化；原始 FreeMote 解包 JSON 也有
非恒等网格关键帧。没有发现这些型号缺少长发或裙摆解算接入。
但相同物理参数映射到各型号的画面幅度确实不同，不能仅比较参数数值判断画面一致。

偏弱还与上一轮交互策略有关：每 tick 的物理原点为 `baseline + movement`，
匀速时该虚拟锚点固定，质量点追上后偏差逐渐减小。它修复累计行程导致的饱和，
同时减弱了持续拖动的反馈。此行为属于本项目可以调整的输入耦合，不是 GPU 后端
或系统资源回收行为；OpenGL 和 Vulkan 共享同一实现。

## 连续速度映射

仍在固定 60 Hz author tick 处理合并后的位移。令 `u` 为本 tick 在作者单位中的
位移，`s = instance_scale * author_scale`，新驱动为：

```text
u = movement / s
q = hypot(3*u.x/32, 3*u.y/12)
driver_author = 3*u / (1+q)
physical_origin = baseline + driver_author*s
```

沿固定方向，输入幅度从零开始连续增加，慢拖近似线性、正常拖动得到更明显反馈，
极快拖动逐渐接近上限，没有快速/正常两个硬档位。方向保持不变；斜拖共享椭圆预算，
某一轴变快会影响另一轴的增益。32/12 为交互策略参数，不冒充源模型系数；
横根映射 0.75、纵向映射 2，使两轴上限对应的输出灵敏度接近。

先分摊 catch-up ticks 再映射，保持同轨迹 30/60 Hz 的物理输入一致。
差值、归一化和限幅使用 double，防止两端有限的 float 相减先溢出。
原始 pending 位移仍按真实位置消费；限幅只影响物理激励，显示位置准确跟随鼠标。
首 tick、暂停、reset、失败恢复和显式 PhysicsInputs 契约不变。

无需再叠加原始加速度：原有虚拟锚点跨 tick 的变化已取决于速度变化，响应起步、
反向与停止。向锚点再加速度差分会增加高频成分；向会累积的 external_displacement
注入速度差分，主要又得到一份速度偏移。此实现选择有界速度输入，沿用既有惯性积分。

限幅保证拖拽注入本身有界，不保证任意动作、外力、模型或瞬间的最终参数/像素幅度
严格单调。原有重力、阻尼、bend、参数夹取和素材变形均保留；匀速后的衰减也仍存在。

## 实测

CPU 几何探针关闭时间线，预热 240 ticks，匀速拖动 60 ticks，再保持 60 ticks。
每次仅替换一条链的输出，其余参数取相同静止实例，排除整体平移。
以 NodeId、source 匹配活动非零透明度图元，固定 3×3 atlas 点采样，避免自适应细分
改变顶点数造成误判。下面为新策略的最大几何采样位移换算到窗口像素，
不是最终无遮挡像素或所有发梢的位移。1920×1080 fit 的 scale 分别为
Chocola 0.557150、Vanilla 0.546118。

| 型号 | 水平速度（px/s） | 双马尾采样峰值（px） | 裙摆采样峰值（px） |
| --- | ---: | ---: | ---: |
| Chocola/wintermaid | 120 | 4.65 | 7.01 |
| Chocola/wintermaid | 480 | 9.97 | 14.94 |
| Chocola/wintermaid | 1440 | 13.15 | 19.57 |
| Vanilla/wintermaid | 120 | 5.63 | 8.05 |
| Vanilla/wintermaid | 480 | 11.98 | 17.16 |
| Vanilla/wintermaid | 1440 | 15.73 | 22.56 |

480 px/s 的旧策略后发采样峰值分别为 8.01 / 9.74 px；新策略正常拖动增强，
极速输入则受约束。纵向 1440 px/s 的旧策略物理输出约 34.3，超过素材 ±30 范围；
新策略约 21.5。不能简单全方向乘三，也不能把上限当作只增大幅度的开关。

独立只读复核另测四个 wintermaid × scale 0.5/2 × 五组速度/方向，共 40 场景：
预热 240 ticks、正向 60、反向 60、停止 240，速度/方向为作者单位每 tick 的
(1,0)、(8,0)、(30,30)、(300,300)、(300,-300)。采样的全部链输出有限，最大绝对值
29.90251；这些场景全程未超过 ±30，停止后没有夹取等待。同作者速度的两种
scale 峰值差为零。惯性仍需衰减：高速斜拖停止后，后发偏差超过 1 可持续约
93 ticks，未被几何引用的 quake spare 可约 228 ticks，不能宣称松手立刻静止。

可见 X11 player 窗口验证两个角色的 wintermaid，覆盖 OpenGL / Vulkan、
1920×1080、fit、60 FPS 预算、静音、no-save，输入只走应用自己的 Controller 回调。
有六次诊断截图，GPU 读回影响这些运行的帧率，不作为性能基准；
真实 Plasma 插件的主观手感仍需用户确认。

Release / LTO / Werror 全构建通过；必选 CPU CTest 218/218，GPU CTest 4/4
（GL、GLES、Vulkan、Python 图形检查），素材集成 13 通过、2 跳过
（原始素材导入环境变量未设置、CJK 字体缺失）。新增一项速度连续性、作者单位上限、
斜向、镜像、缩放、极端有限输入及反向 catch-up 测试；更新原拖拽参考输入。
原有 catch-up 零分配、暂停/reset/失败恢复和 30/60 Hz 用例继续通过。

## 性能和资源边界

只新增程序和实例各一个 author_scale float；没有新增容器、队列、GPU 资源、
线程、依赖或几何求值。无移动时直接返回零；移动时每物理 tick 计算一次映射。
现有 runtime 分配用例覆盖连续 drag、advance、prepare，仍为零堆分配；
不把该结论扩展成整个应用或驱动的零分配。

CPU 对照：Xeon E5-1680 v4、GCC 15.2.1、Release/LTO，固定 CPU 2，
Chocola/wintermaid scale=1，Controller 内部回调，音频关闭，无 UI/窗口/GPU。
轨迹 `x=120*sin(.03*t), y=80*sin(.017*t)`，advance=1/60，随后 prepare；
预热 240 ticks，计时 10000 次排除前 500 次，只计 pointer_move+advance+prepare。
三轮交替旧/新二进制，所有构建、测试、窗口和独立压力探针完成后串行采样。

| 轮次 | 原 P50/P95/P99（ms） | 新 P50/P95/P99（ms） |
| --- | --- | --- |
| 1 | 0.621612 / 0.634149 / 0.660405 | 0.620790 / 0.632847 / 0.644329 |
| 2 | 0.622840 / 0.637915 / 0.722738 | 0.620979 / 0.636347 / 0.648737 |
| 3 | 0.622148 / 0.638165 / 0.709508 | 0.621797 / 0.658992 / 0.833611 |

P50 基本持平；第三轮新策略 P95/P99 有升高，尾部波动未归因，不宣称所有分位
性能不变，也不把不同姿态或波动宣布成 CPU 性能收益。
GPU 执行原来的绘制协议；本轮没有增加显存资源，也没有独立测量整机功耗或
完整桌面 CPU/GPU 使用率，不能据此承诺所有姿态的设备耗时完全相同。

## 素材差异和剩余范围

Chocola/dress（礼服原版，与 wintermaid 不同）后发输出对应的原始网格关键帧均为
近似恒等，误差约 3.34e-8；单独强制 ±30 也没有几何变化。这属于素材本身，
不能通过加大拖拽增益补出变形。

195 型号中 319 条缺导出锚点的链有 315 条输出未被几何引用。另四个 Azuki
maid-b、maid-b-custard、santa-b、wintermaid-b 的侧发输出确实影响活动几何，
但原始 JSON 同样缺失对应锚点。是否需要外力驱动尚需原网页对照；本轮未修改
固定零锚点语义，不能把它们归为已经修复或无用的模板。
