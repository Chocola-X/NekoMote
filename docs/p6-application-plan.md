# P6 原生应用会话实施记录

当前基线 2026-10-04；运行时已接通作者动画、混合差分、外部参数差分、全部首发模型物理和 GL 渲染。冻结阈值和现有 FAIL 继续保留，以下步骤不能替代模型求值验收。

1. 离线导出模型 profile、展示参数和角色反应规则，写入独立强类型 SessionAsset；原始 JS 只在离线工具执行，不进入核心或正式播放。明确缺失动作/变量的规范化诊断，不硬编码外部参考路径。
2. 建立 CPU application 会话：单一作者时钟、局部输入能力、视线返回、触摸区域和优先级、动作槽、节拍/恢复、独立口型通道。编译后只用 ID/数值，无显示服务器的生命周期/时序/堆分配验证。
3. 解码真实 PCM 音频并加载缓存；设备服务与会话分离，有界控制与实际播放位置/音量快照，暂停/停止/销毁不在渲染线程等待设备。声音失败显式报告，不模拟发声。
4. 普通窗口集成鼠标、拖动/缩放、暂停、反应、声音及背景；用确定输入核对参考截图，测量完整正常播放的 CPU/GPU/呈现与资源。
5. 继续关闭已记录的物理/边缘精度，拓展真实型号动作与遮罩。完成一复杂模型后再建立 Plasma 宿主契约与可安装产物，不改用户桌面设置。

每个实际实现块更新此文件、开发日志和证据；相关检查通过后提交。现有差分矩阵中的单像素和头发物理误差未通过时不宣布 P3–P6 完成。

## 已验证：CPU 会话与离线规则（2026-10-04）

- SessionAsset v1 独立于 ModelAsset v5：只保存 author-space 触摸椭圆、动作槽、ID 标签、作者节拍、恢复及相对音频引用。`nekomote::application` 仅依赖 runtime，不依赖 JSON、文件系统、窗口或设备。
- 会话复用 PlaybackInstance 唯一的 60 Hz 作者时钟；输入只报告本地 surface 能力。动作、节拍、忙状态、视线返回、口型差分、暂停及 reset 有独立实例状态。设备控制通过 8 项有界队列；容量失败明确返回并按部分求值是否发生决定 fault。
- 正式导入命令：`python3 tools/import_session/import_session.py --reference-root ../NekoWebShow --model chocola-date-a --output <asset-dir>/session.nks.json`。需要离线 Python 3 与 Node（本次 23.9）；只执行原项目作者的两个规则文件，不执行模型 asm 核心。原模型/规则只读；仅复制选定角色反应所需声音。导入报告记录 hash 和所有缺失绑定规范化。
- 真实 Chocola/Vanilla/Fraise 分别 20/21/18 项反应导入并编译，均 0 规范化警告。Debug/Release 116/116，ASan/UBSan 115/115（无 GPU）通过；Python 9/9。1,000 作者步覆盖交互、反应、口型、构帧，项目控制的普通 `new` 次数 0。这里只证明 CPU 会话路径，不代表音频设备或整个壁纸功耗。
- 完整帧诊断现在保存 xyuv+RGBA、遮罩和混合协议。`nekomote_frame_render MODEL OBSERVATION_JSON OUTPUT_PNG` 是独立诊断工具，只重放观察值；生产播放器必须使用本项目自己的 PlaybackInstance 输出。旧四列观察文件须重新生成。
- `reaction-h01` 原 PSB 36 步动作与会话输出对照仍为已知单像素 FAIL。零时长输入案例只替换 tex/0076 后髪绘制命令的诊断顶点位置即 PASS；替换 UV 仍 FAIL，错误地将参考 vertex RGB128 当作中性颜色产生大面积失败，已拒绝该实验。源着色器该通道并不等同本项目颜色协议，不能据此修改正式颜色。未把参考顶点作为生产输入或放宽阈值。
- 证据：`build/evidence/p6-application/`，包含全部构建/测试日志、三角色导入资产、会话观察、诊断对比和未截断 38,533 项原 SDK 数值写入观察。既有 FAIL 全部保留；后续应继续后髪浮点几何和物理精度调查。
