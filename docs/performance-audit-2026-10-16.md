# 长期壁纸运行占用核查（2026-10-16）

核查源码 `6dcd5861c28a8338b076030fe9c7a05a67274b0c`，Codex / GPT-6（精确变体未知）。
本轮为分析与测量，没有修改产品源码、安装插件或修改桌面设置。桌面启用由用户操作。
前序依据为 C13–C17 报告；旧机器数字不能替代本机结果。

## 条件与结论

本机 Intel Xeon E5-1680 v4，8 核 / 16 逻辑线程，RTX 3080 Ti，NVIDIA 580.82.09，
KDE/X11。`xrandr --current` 确认单输出 2560×1440、180 Hz。用户将壁纸设为 60 FPS；
保存的型号为 `chocola/date-b`，背景 BG_47，声音开启，插件选择 Vulkan。
这里记录配置帧率，没有直接测量真实 Plasma 壁纸呈现帧率。

仍有优化空间，但优先级应从细小计算优化移向宿主提交、合成和资源所有权。
RSS 150 MB 不是独占内存，更不是模型自身存活堆大小；也不能说所有驱动/共享库页都免费。
当前材料不支持承诺整机 3%–4% 降至旧机器的 0.4%，或无损地把 RSS 减半。

## 桌面 CPU 观察

通过 `/proc/stat` 和进程 `/proc/PID/stat` 各采样 20 秒；总 CPU 按全部逻辑线程归一化，
与用户所述 btop 整机口径比较。进程表另外保留 100% 为一个核心的数字。
此时未运行项目构建、CPU probe 或 GPU 诊断宿主。其他桌面应用仍在运行。

| 状态 | 整机 CPU | Plasma | KWin | Xorg |
| --- | ---: | ---: | ---: | ---: |
| 用户确认壁纸未启用 | 2.43% | 0.094% | 0.510% | 0.282% |
| 启用后首段 | 4.25% | 1.019% | 0.847% | 0.331% |
| 用户确认运行后稳定段 | 3.34% | 0.965% | 0.639% | 0.141% |

以上都是整机百分比。稳定段 Plasma 对应约 15.38% 的单核口径。
整机读数包含其他程序，不能把 3%–4% 全归因给壁纸。两个启用样本的 Plasma
较关闭段增加约 0.87–0.92 个整机百分点；这只是短时关联观察，不是隔离插件 CPU
的精确归因。KWin/Xorg 及其他应用也有波动；没有多轮关闭/开启交替，不能直接把
整机差值宣称为稳定的产品预算或优化收益。

关闭期间 GPU 快照约 210 MHz / 36 W；启用期间一次快照约 990 MHz / 52 W。
`nvtop --snapshot` 分别出现 8% 和 41% 利用率。它们是异时快照，不能作为壁纸的
精确功耗差；低频时的利用率也不能直接解释为占用显卡峰值算力的同样百分比。

180 Hz 是显示器刷新率，不等于壁纸求值或提交 180 FPS。
当前源码 `adapters/plasma/wallpaper_item.cpp` 已读取共享 FPS，60 对应 17 ms 定时器；
旧文档的“FPS 尚未联动”不再是当前源码缺陷。实际安装版本和真实回调次数仍应通过
诊断验证。2K 比 1080p 多约 78% 像素，主要影响像素处理和合成，不能按同倍率推算
参数/物理/几何 CPU，也不能把 180/60 再乘进壁纸的实际渲染次数。

## 本机 CPU 核心拆分

独立无窗口 Release/O3/LTO 构建，GCC 15.2.1，固定 seed=1。
诊断 harness 通过现有 `SessionInstance` API 启动真实 idle 动画，音频设备关闭，
不输入视线/触摸；origin=(0,0)、scale=1，预热 360 次 advance+prepare，
采样 10000 次，每次 advance(1/60)，每型号独立进程重复两轮。
循环内不做 JSON、绘图、I/O 或截图；计时包含两次阶段边界时钟调用。

| 型号 | advance P50 ms | prepare P50 ms | 总 P50 ms | 平均进程 CPU ms/步 |
| --- | ---: | ---: | ---: | ---: |
| Chocola date-b | 0.100 | 0.348–0.349 | 0.448–0.449 | 0.452–0.454 |
| Chocola date-a | 0.097 | 0.394 | 0.491 | 0.490–0.491 |
| Fraise maid-b | 0.195–0.196 | 0.751–0.752 | 0.947–0.948 | 0.951–0.952 |
| Fraise casual-a | 0.197–0.199 | 0.777–0.778 | 0.975–0.977 | 0.982–0.991 |

date-b 末帧约 4375 顶点、21720 索引、34 条颜色命令。
prepare 含最终 geometry.evaluate 和 build_frame，不能把它全称为变形函数耗时。
按本机平均 0.453 ms × 60 次/秒折算，核心约 2.72% 单核，即约 0.17% 整机。
这是特定诊断输入下的成本估算，不是实际 Plasma 的线程 CPU 直接测量。
若该核心整体加速 25%，在这些条件下只相当于约 0.04 个整机百分点，解释不了
从整机 3%–4% 到 0.4% 的全部差距。因此先检查提交/宿主路径更有价值。

另执行现有 playback_probe：240 author ticks、预热 120、每轮 10000，4 型号各两轮。
这个输入没有播放 idle timeline，属中性参数/物理基线，不能混用为真实 idle 成本；
其 date-b P50 约 0.219 ms。两种入口不同的状态也说明仅有型号名不足以复现性能。

## RSS、PSS 和私有页

用当前 `build/release/bin/nekomote_abi_host`（重新构建检查为 no work）运行四组隐藏窗口
诊断：GL/Vulkan × model-only/完整 assets+展开 UI，1920×1080、seed=1、静音、不保存。
各运行 4000 个固定步长，在日志出现 frame 300 后每约 400 ms 读取 smaps。
下表取剔除最后两个样本后的中间样本，以避开末尾截图像素读回/PNG 分配。
这是固定步长、非限速资源诊断，不是 60 FPS 的 CPU、功耗或真实 Plasma 内存基准。

| 完整 assets+UI | RSS MiB | PSS MiB | Private Clean+Dirty MiB | 驱动关联映射 RSS MiB |
| --- | ---: | ---: | ---: | ---: |
| OpenGL | 132.14 | 61.14 | 56.59 | 94.88 |
| Vulkan | 165.43 | 77.10 | 55.14 | 122.17 |

驱动关联映射按路径含 nvidia、/dri/、/dev/dri 或 /dev/nvidia 分类，包含共享与私有页，
不等于驱动独占堆。普通匿名映射约 23.6 / 29.6 MiB，也包含分配器和第三方分配，
不能全部标成项目对象。字体文件实际驻留约 0.28 MiB，当前不是整份 TTC 都在 RSS。
两种后端各一轮，有分配器及驱动状态差异；不将差值保证为真实桌面切换后的内存收益。

- RSS 会完整计入共享驻留页；PSS 按当前共享进程数分摊，因此会随系统其他进程变化。
- Private Clean+Dirty 更接近当前该进程专有的驻留页，仍不等于不可回收或项目存活堆。
- Plasma 插件在 plasmashell 内运行，整个 Plasma 的数百 MiB RSS 不能当成插件占用。
- 本表关闭音频，不能拿它声称用户声音开启时占用相同；2K 中间目标/驱动映射也可能不同。

## 优化候选与性价比

| 优先级/工作 | 成立证据与收益边界 | 工作量与性价比 |
| --- | --- | --- |
| 高：本机 Plasma GL/Vulkan 同条件对比，细分求值/提交/共享图像/合成 | 当前 Vulkan 经 Qt OpenGL 合成，桥内有 fence、GPU semaphore 和一次全输出 glBlitFramebuffer；原生 Vulkan player 的结果不能套用。仅凭这些不能断言 GL 一定更快 | 对比成本低，应先测；进一步优化由实测热点决定 |
| 高：音频库单份不可变所有权 | ABI create_audio_device 先复制 candidate.audio_clips 到 audio_clips_，再移交另一份给 Device；player 同样保留副本。date-b 的 19 份语音解码 float+RMS 一份合计 6075300 bytes，约 5.79 MiB | 小到中。共享同一不可变 bank，保留静音恢复、线程和候选失败寿命；可明确减少一份存活数据，实际 RSS 还受 allocator 保留页影响。静音未加载时没有这项收益 |
| 中：缩小或限制颜色中间目标有效绘制区域 | ProtectedStraight 每角色使用整输出 RGBA8，并做最终全输出合成；2K 单份 RGBA8 约 14.06 MiB。保留输出分辨率，按完整动态几何范围处理透明空区有潜力 | 中到大。先做 GPU 时间 profile；必须保留像素对齐、过滤、遮罩映射、镜像、缩放、拖拽及渐变，不能承诺把整份 14 MiB 全省掉 |
| 中：最终几何热点与有界缓存 | 真实 idle 的 prepare 是核心主要阶段。网格采样比值、曲面链与变化传播值得 profile；索引/UV CPU 缓存已做过，不重复列为未实现 | 中到大，整机绝对收益受约 0.17% 核心成本约束。严格保持 Float32 保存边界与数值顺序；不直接开启 fast-math 或降低细分 |
| 中低：稳定拓扑时 GPU 索引上传复用 | GL prepare 仍每帧上传 EBO，VK 仍复制索引。date-b 当前约 85 KiB/帧，即约 5 MiB/s，带宽并不大；收益可能主要来自少一次 API/驱动操作 | 中。需要可靠内容版本/失效契约，指针相同不能证明内容没变；先测提交热点 |
| 低：收起面板的 UI 优化 | sidebar 收起后不构建菜单；展开时才有文本/逐行提交、不可见项仍生成数据等候选 | 小到中，但对长期收起面板的主场景收益有限，不优先为新多语种功能背锅 |
| 低：G34 重复几何编译 | 重复编译仍存在；本机 compile_session 约 2.8–4.4 ms，而模型/会话读取约 70–113 ms | 有结构收益，但只影响加载/切换；不能解决稳态占用，不优先于帧路径 |
