# X11 / EWMH 独立壁纸壳

2026-10-21 双后端交付与限定验收见 [报告](shell-vulkan-2026-10-21.md)。

`adapters/x11/` 是独立进程薄壳，仅经高层 C ABI 使用现有模型、背景、音频、
控制面板和配置。默认关闭，不依赖 Qt、GTK、XFCE 私有 API 或 GLFW。
分发基线为 Ubuntu 20.04 / GCC10 / glibc2.31，图形可选 OpenGL3.3 core / GLX
或 Vulkan1.0 / Xlib surface，默认 OpenGL。
基线约束的是库和符号要求；桌面图标能否共存仍需按宿主验证。

## 协议与能力

使用正式的 [EWMH 窗口属性](https://specifications.freedesktop.org/wm-spec/latest/ar01s05.html)：
`_NET_WM_WINDOW_TYPE_DESKTOP`、全工作区 `_NET_WM_DESKTOP=0xffffffff`、
跳过任务栏/分页器状态，以及 ICCCM 的无键盘焦点提示、客户端机器名和正常关闭协议。
启动时验证 WM 的双向 `_NET_SUPPORTING_WM_CHECK` 和必需 `_NET_SUPPORTED` 项。
不支持则明确失败，不改为普通置底窗口。

输出经 [RandR](https://www.x.org/releases/current/doc/randrproto/randrproto.txt) ≥1.3 查询，
一进程绑定一个已连接输出，默认主输出或第一个活动输出；尺寸/位置变化更新窗口和 ABI，
选中输出移除后退出。无扩展或无活动输出明确失败。输入穿透使用正式
[Shape 1.1](https://www.x.org/releases/current/doc/xextproto/shape.html) Input 区域，
没有该能力则拒绝穿透模式。GLX 使用 Khronos 的
[ARB_create_context](https://registry.khronos.org/OpenGL/extensions/ARB/GLX_ARB_create_context.txt)
和 core profile 扩展。

X11 连接、图形设备和 ABI 由一个线程串行拥有；OpenGL 销毁顺序为壁纸/工作线程、
GLX、窗口、连接；Vulkan 先停止设备工作，再销毁壁纸、共享呈现宿主、窗口和连接，
部分初始化失败也回收。事件批次有界，按共享 FPS 限制和 poll 等待调度，
正常绘制不轮询窗口属性、不上传截图、不做 glFinish 或每帧 XSync。
隐藏时通知独立的输出不可用状态、排出音频暂停命令并停止绘制；恢复重置时间基线，
不覆盖用户暂停。角色渐变与背景/动画使用相同的暂停和250ms时间预算。

只转发本窗口收到的指针、左右键、滚轮、进入/离开；UI 命中和模型交互归共享应用层。
不获取键盘焦点、全局指针，不承诺全屏遮挡自动暂停；右键桌面菜单不由此壳重建。
没有 root pixmap 播放、其他窗口重挂接、强制循环降低层级或修改桌面配置。
Vulkan 分支使用默认 X11 visual 创建原生窗口，不初始化 GLX；经共享
`nekomote::host_vulkan` 创建实例、设备、swapchain 和单帧提交，并向高层壁纸 C ABI
提供借用的录制目标。事件处理和 advance 前等待上一帧 GPU 完成，避免输入、尺寸变化
或异步角色交接释放仍在引用的资源；重建与 out-of-date 恢复由共享宿主管理。

## 构建与使用

```bash
cmake --preset x11
cmake --build --preset x11 -j4
build/x11/bin/nekomote_x11 --list-outputs
build/x11/bin/nekomote_x11 --assets /path/to/assets --output HDMI-1
build/x11/bin/nekomote_x11 --assets /path/to/assets --backend vulkan
```

`--backend opengl|vulkan` 只选择本次运行后端。Vulkan 需要构建时启用
`NEKOMOTE_BUILD_VULKAN=ON`（另需 Vulkan 头文件、loader 与 glslangValidator）；
未启用的二进制明确拒绝 `--backend vulkan`，运行时设备/呈现失败也明确退出。
没有自动切换后端或保存启动参数，本轮不改变配置布局。

`--input interactive` 为默认；`--input passthrough` 完全留空本窗口输入区域，
因此无法在该窗口操作共享面板。`--ui-open` 可在交互模式启动时展开面板。
`--mute` 强制静音，`--no-save` 禁止写配置。
默认配置位于 `$XDG_CONFIG_HOME/nekomote/x11/output-<输出名UTF-8十六进制>.json`，
未设 XDG 时为 `$HOME/.config/` 下相同路径，也可显式 `--config FILE`。
资产目录不作为默认写入位置；多输出实例应各用独立配置，每个输出仅启动一个实例。

`--model FILE [--session FILE]` 是共享 ABI 的单模型诊断模式，不提供资产目录面板。
`--frames N [--capture FILE.ppm]` 固定每步1/60秒，自动静音/禁止保存；截图只在
最后一步读取一次 framebuffer，目标文件已存在则失败，不混入正常资源测量。
指定 `--capture` 时 Vulkan 仅绘制/读取共享离屏 RGBA8 输出，不经过 swapchain 呈现；
按黑色底合成后写入同方向的 PPM。该检查不能证明桌面最终合成与呈现正常，
需要另行执行无 capture 的运行验证；正式播放不读回。

## XFCE 共存边界

EWMH 定义 DESKTOP 属于最低堆叠组，但没有把一个桌面窗口的背景与图标拆成两个表面，
参见 [堆叠规则](https://specifications.freedesktop.org/wm-spec/1.5/ar01s09.html)。
[xfdesktop 的职责](https://docs.xfce.org/xfce/xfdesktop/start) 包括背景、图标和桌面菜单。
这些标准接口长期可用，不等于存在通用的“插到背景和图标之间”接口。

Ubuntu20 的 xfwm4 4.14.1 / xfdesktop4 4.14.2 隔离验证中：没有 xfdesktop 时，
壁纸正常占用桌面层；保留 xfdesktop 并启动壁纸时，壁纸可见，但覆盖了背景和图标。
因此本轮只交付通用 EWMH 壳，**没有完成 XFCE 原图标/菜单共存适配**。
启动时发现其他 DESKTOP 窗口会输出提示，不擅自停止 xfdesktop、改其配置或降低现有窗口。
后续若要保留 XFCE 图标，应单独确定其公开接入方式；不能用同层窗口排序冒充完整适配。

## 项目内隔离验证

无需安装 XFCE 到主机。可在项目 `build/x11-validation/rootfs/` 内准备 Ubuntu20 文件树，
用现有 user namespace + bubblewrap 绑定为私有根目录，`/tmp`、D-Bus、HOME/XDG 均独立。
显示验证还使用网络命名空间，隔离 abstract Unix X socket；不只依赖私有 `/tmp`。
源仓库只读绑定 `/source`，证据目录绑定 `/work`；只把父显示的 X socket 和认证文件
只读提供给 Xephyr，用于展示一个正常窗口。被测应用仅连接 Xephyr 的私有 `:91`，
不向真实桌面注入输入。需要现有的 namespace/bubblewrap 能力，脚本不安装主机软件包。

可选容器镜像配方为 [x11_validation.Containerfile](../tools/x11_validation.Containerfile)，
基于已有 Ubuntu20 CI 镜像；只在隔离根内安装 Xephyr、xfwm4、xfdesktop、D-Bus、
X11 诊断工具和 Mesa 软件驱动。这个镜像不参与发布构建。
本次实际复用并克隆了项目已有的 focal CI 根文件树，未改变该原树或主机包。

进入上述隔离环境后，在可写 `/work` 下构建，不能向只读 `/source/build` 写 preset 产物：

```bash
cmake -S /source -B /work/build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INTERPROCEDURAL_OPTIMIZATION=ON -DNEKOMOTE_WERROR=ON \
  -DNEKOMOTE_BUILD_X11=ON -DNEKOMOTE_BUILD_ABI=ON -DNEKOMOTE_BUILD_TESTS=ON \
  -DNEKOMOTE_BUILD_PREVIEW=OFF -DNEKOMOTE_BUILD_PLAYER=OFF \
  -DNEKOMOTE_BUILD_TOOLS=OFF -DNEKOMOTE_BUILD_VULKAN=OFF
cmake --build /work/build --target nekomote_x11 nekomote_x11_probe \
  nekomote_x11_option_tests nekomote_unit_tests -j4
# 父显示 socket/认证由隔离器绑定，以下路径均位于私有根目录。
PARENT_DISPLAY=:0 PARENT_XAUTHORITY=/parent-xauth \
NEKOMOTE_X11_VALIDATION_ROOT=/work/desktop \
bash /source/tools/x11_validate_desktop.sh \
  --binary /work/build/bin/nekomote_x11 --probe /work/build/bin/nekomote_x11_probe \
  --model /source/assets/characters/chocola/date-a/model.nkm \
  --session /source/assets/characters/chocola/date-a/session.nks.json \
  --assets /source/assets --evidence /work/desktop/checks
```

检查工具依赖 Python/Pillow、默认 Xephyr 输出名 `default` 和1280×720初始尺寸，
证据目录须不存在。脚本创建私有 D-Bus 和可见 Xephyr，运行真实 xfwm4/xfdesktop，
用显式本程序 XID 检查属性、输入区域、隐藏恢复、1024×768调整、诊断截图和共存；
不按窗口标题查找，不发送系统键鼠输入。`nekomote_x11_probe` 仅为显式构建的测试程序，
截图读回不进入正式播放路径，也不进发行包。
