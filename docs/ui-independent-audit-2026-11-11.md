本轮检查上次 Codex 提交 `38beb2a` 之后的三项提交：

| 提交 | 内容 | 结论 |
| --- | --- | --- |
| `df2f08a` | 音量滑块、配置与音频缩放 | 功能保留；修复拖动捕获、最终释放坐标、显式静音时配置加载及 player 当帧同步 |
| `475ed18` | 布局裁剪、UTF-8 流式解码及度量缓存 | 保留裁剪与流式生成；撤销跨实例共享 footer 缓存 |
| `1d35e72` | GL/Vulkan 相邻批处理 | 保留兼容批次；撤销改变抗锯齿的捷径，修复资源边界，并消除单色批次的额外上传成本 |

## 1. 实际问题与处置

1. **零半径矩形依然有抗锯齿。** 原 rounded-rect shader 在边缘应用 smoothstep，
   半径为0不代表可改用纯色三角形。两后端同时改错会通过 GL/Vulkan 相等检查。
   现恢复原 shader；新增整数/小数坐标的边缘 alpha 断言，另外保留双后端图像比较。
2. **字体扩容会破坏尚在使用的数组。** `draw_text` 记录追加位置后，字形准备可能
   触发 atlas resize；原回调 `flush_text()` 清空同一数组，追加位置不再有效，后续
   可能下溢或越界。现按旧/新 atlas 尺寸调整已排队 UV，不改变借用数组长度；
   扩容回归与显式提前提交的画面逐字节相同，测试确认实际发生了 atlas 扩容。
3. **延迟提交延长了资源寿命。** GL 更换字体、销毁仍被排队图元使用的图标、
   改变视口前必须提交旧图元。现补齐这些边界；目标切换沿用下次 `begin_frame`
   生效的既有行为，并明确记录和测试。alpha 保留调用时数值。
4. **footer 函数静态缓存不属于某个实例。** 多输出线程可同时写同一缓存；字体
   对象原址重建也可能复用旧度量。撤销此缓存，每帧计算两个短字符串，避免增加
   缓存失效机制。保留实例内、具有当前调用条件的百分比格式化缓存。
5. **滑块捕获可以残留。** 关闭菜单、折叠设置、滚动剔除滑块、输出不可用或暂停时
   需要取消拖动；按钮已释放时不能继续抢模型输入。正常 Release 仍消费最终位置，
   包括同帧按下/释放。取消接口不合成 Release，防止恢复后将按住的图标误判为点击。
6. **配置与音频同步。** 显式设置 mute 后再加载 assets，不应跳过已保存的 volume，
   特别是0；volume 读取移出 mute 条件。player 之前在菜单已更新 config 后再比较
   volume，令当帧更新条件恒假；现比较构建菜单前的值。原来下轮 advance 仍会设置
   设备音量，因此这是当帧同步缺失，而不是音量永久不生效。另删除重复设备赋值。
7. **减少 draw 不一定减少成本。** 初始批处理为每串文字上传额外颜色数组，即使
   整批同色。现将单色批次作为常量顶点属性，只有出现第二种颜色才补齐颜色数组；
   保留透明顺序、裁剪边界和混色批次。GL/GLES 均检查单色→混色→单色及 alpha 变化。

原 `1d35e72` GL 实现运行新增边缘/资源负例，2项均失败；修复后通过。
证据见 [original-negative](validation/ui-audit-2026-11-11/ui-batch-original-negative.txt)。
未冒险在已知数组下溢的原版执行大容量 atlas 回归，不宣称该原版负例已运行。

## 2. 同条件分阶段实测

### 条件与边界

- Manjaro，Linux 6.6.107，Xeon E5-1680 v4（8核16线程），RTX 3080 Ti，NVIDIA 580.82.09。
- GCC15.2.1，Release `-O3 -DNDEBUG`、LTO、项目 Werror；独立构建目录，未混用 Debug。
- 本轮环境 `XDG_SESSION_TYPE=x11`，探针报告 GLFW X11（393220），OpenGL3.3。
  这不是先前用户 Wayland 会话的性能认证。
- 同一真实 `assets/` 目录、8个角色组、英文、默认字体36px、800×1080输出、零滚动、无输入。
  角色组由目录排序，场景2是 **Azuki（第一个角色组）**，不是 Chocola。
- 探针调用真实 `build_sidebar` 与 GL renderer；不加载/求值模型，不播放音频，不呈现。
  `animation=0` 的样本仅测关闭的 sidebar，不包含右侧控制图标。
- 每场景预热300帧，采样1200帧，三轮轮换版本顺序、串行运行。
  原生桌面继续正常运行；没有固定CPU频率，因此保留调度和驱动波动。
- 帧内 wall 时间含 GL 提交与 `glFlush`，不含 `glFinish`、交换或截图。
  另用进程 CPU 时钟记录整段采样的 CPU 均值，含极少量计时记录开销。
  绘制计数只在采样后的一帧开启，RGBA 读回也在计时之外。

版本：baseline=`df2f08a`（音量功能已有，但两阶段优化未实施）；layout=`475ed18`；
initial=两阶段优化加正确性修复、尚无单色属性路径；candidate=本轮最终代码。
`38beb2a` 尚无滑块，不能把不同设置内容当作纯优化对照。

## 4. 复现方法

新增独立工具 [ui_menu_probe.cpp](../tools/perf_compare/ui_menu_probe.cpp) 与
[CMake注入入口](../tools/perf_compare/ui_menu_probe.cmake)，可用同一源码测试隔离的旧提交。
不向产品常规构建或播放流程加入探针。

```bash
# repo为含探针的当前仓库；checkout为冻结提交的独立worktree。
cmake -S "$checkout" -B "$build" -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_INTERPROCEDURAL_OPTIMIZATION=ON \
  -DNEKOMOTE_WERROR=ON -DNEKOMOTE_BUILD_PREVIEW=ON \
  -DNEKOMOTE_BUILD_TESTS=OFF -DNEKOMOTE_BUILD_VULKAN=OFF \
  -DCMAKE_PROJECT_nekomote_INCLUDE="$repo/tools/perf_compare/ui_menu_probe.cmake"
cmake --build "$build" --target nekomote_ui_menu_probe -j 3
"$build/nekomote_ui_menu_probe" "$repo/assets" "$output_prefix"
```

输出包括驱动/平台、五场景计时、draw计数与独立RGBA文件。目录、语言、菜单状态和字体
需保持一致；截图与实际显示帧率不在同一测量范围。最终二进制指纹见
[color-binaries.json](validation/ui-audit-2026-11-11/color-binaries.json)。
本轮实际构建沿用临时目标名 `ui_independent_probe`，提交的注入入口改为正式诊断目标名；
已执行源码和格式化后工具的指纹均记录在 `inputs.json`，两者只有格式差异。
