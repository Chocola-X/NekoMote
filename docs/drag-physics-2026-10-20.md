# 拖拽时的实时物理反馈

基线 `8e850c0`，2026-10-20，Codex / GPT-6（精确变体未暴露）。

拖动原先直接更新模型世界原点，物理锚点也跟着累计移动。输入没有等待松开：
GLFW、Qt Quick、X11 和 layer-shell 都在推进、绘制前提交输入。但软弹簧的质量点
追赶累计位移时，输出会超过模型几何使用的参数范围，画面在边界保持同一姿态，
直到质量点追上才恢复可见变化。这解释了“位置跟随、物理迟些才动”的一种实际原因，
没有发现固定一秒的延迟计时器，也不把主观一秒视为已经精确复现。

真实 Chocola `date-a` 的受控 Playback 重放（不播放时间线）：预热 240 个
60 Hz author ticks，随后每 tick 水平移动
30 像素，共 20 ticks / 600 像素，再保持位置 100 ticks。几何使用的相关参数范围为
±30；原策略的 `hair_LR_M` 停下后的首 tick 为 -38.432777，直到 tick 42 才回到范围内，
即停止后 22 ticks / 约 0.367 秒。这段时间画面会被夹在边界。

初期检查也发现没有导出锚点的侧发控制器，但未采用对应候选修复：195 个模型中的
319 条缺锚点链有 315 条输出完全没有被几何引用，date-a 的两条侧发链也没有引用。
参数能变化不等于实际画面有改善；保留原来的固定零锚点语义。

## 实现

共享 Controller 的按住拖动改走 `SessionInstance::drag_origin()` 和
`PlaybackInstance::drag_origin()`，显示位置继续准确跟随鼠标。物理锚点的外部拖动
贡献改为每 author tick 的位移，即一个物理步的速度驱动，不再累积整个屏幕行程。
停止移动时贡献在下一个 tick 归零，由原来的积分状态继续产生惯性反馈。
这是对交互耦合的产品行为调整，不是修改 E-mote 解算公式。

物理阶段暂时使用“基准原点 + 本 tick 位移”，完成后恢复显示原点。
复用原有的物理锚点求值和最终绘制求值，不增加 evaluate 次数；不更改 spring、chain、
bend、重力、摩擦、时间步或资产。显式 `PhysicsInputs` 外力契约不变。

- 多条鼠标移动合并；没有 author tick 时保留待消费位移，prepare 不消费。
- 多 tick 追赶均分位移，避免重复施力；30/60 FPS 的同一匀速轨迹输出一致。
- 首物理 tick 仅初始化，不留下反向伪激励。暂停/恢复丢弃旧 pending。
- 物理失败也恢复显示原点；reset 后保留正确位置。
- 交互后直接设置位置只重基准 pending，保留物理参考，避免 fit/重定位重新灌入
  整段拖动距离。reset 恢复直接放置模式；接口头文件明确此状态契约。
- 镜像、模型/author scale 继续由现有几何与物理变换处理。

新策略仍允许非常快的一次移动产生强烈反馈，没有承诺任意速度都不触及参数边界。
它消除的是随累计行程增加而长期卡住的驱动。

## 验证和资源边界

新增四个合成测试覆盖：按住期间首 tick 反馈、累计 3600 像素后的匀速/停止反馈；
镜像和缩放；高频 move 合并和无 tick 准备；30/60 Hz 追赶；初始化、暂停、重定位、
改 scale 和有效实例物理失败后的 reset。原有预热零堆分配用例加入连续拖动与双 tick
追赶，测得项目控制的该段 advance/prepare 仍为零分配。
这项分配检查覆盖 runtime，不据此推定整个 Controller、UI 或驱动零分配。

真实 date-a 相同 120 ticks 的旧/新策略，参数超过 ±30 的 tick 数：

| 参数 | 原驱动 | 新驱动 | 新驱动停止后的首 tick |
| --- | ---: | ---: | ---: |
| bust_LR | 33 | 0 | 26.226866 |
| hair_LR | 41 | 0 | 0.589283 |
| hair_LR_M | 91 | 0 | 7.518269 |

本地可见 player 窗口以 X11、1920×1080、60 FPS 预算、fit、静音、no-save 验证
OpenGL 和 Vulkan。只通过应用自己的 Controller 回调重放拖动，不注入系统输入，
不安装桌面插件或保存用户配置。NVIDIA RTX 3080 Ti / 580.82.09；诊断截图在拖动中和
停止后采集。截图和 GPU 读回影响这些诊断运行的帧率，因此不作为性能基准。
普通 EGL vblank 等待在本机可能停住未聚焦窗口；本次使用可见窗口的显式帧预算模式
关闭该等待，与日常正常 vblank 路径分别记录，不假称已验证用户实际桌面插件。

实现只为每实例增加三个 Vec2 和一个标记，没有 GPU 对象、纹理、线程、队列或依赖。
GPU 仍执行原绘制协议；姿态变化可能自然改变选中的几何，不能据此承诺所有动作的
CPU/GPU 数值完全相同。独立只读复核通过。

Release / LTO / Werror 完整构建通过。最终必选 CPU CTest 217/217；图形 CTest 4/4
（OpenGL、GLES、Vulkan 和 Python 图形检查）；素材集成 13 通过、2 跳过（原始解包素材
环境变量未设置、CJK 字体环境缺失）。完整单元 runner 为 220 通过、1 素材跳过。

CPU 隔离采样使用 Xeon E5-1680 v4、GCC 15.2.1、Release/LTO 依赖，固定 CPU 2，
音频关闭，无窗口、UI、GPU 或截图。真实 date-a，scale=1，Controller 内部回调持续拖动：
`x=120*sin(0.03*t)`、`y=80*sin(0.017*t)`，每次 advance=1/60，随后 prepare_frame。
先预热 240 ticks，计时 10000 ticks 并排除前 500 个，三轮交替运行原/新二进制。
仅计 pointer_move + advance + prepare；不覆盖完整桌面呈现和设备线程。
