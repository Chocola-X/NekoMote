# P7 性能对比：原生引擎 vs WebGL 引擎

**日期**：2026-10-07 12:18:10  
**提交**：869a960  
**模型**：chocola-date-a  
**控制变量**：1920×1080，目标 60 FPS，预热 120 帧，测量 300 帧  
**GPU**：NVIDIA GeForce RTX 3060 Laptop GPU  
**测量方式**：串行执行（避免 GPU 互相干扰），每 100ms 采样进程树 CPU/RSS + nvidia-smi GPU/VRAM

## 1. 帧时间与 FPS

| 指标 | 原生 (preview) | WebGL (chromium) |
|---|---|---|
| render+swap P50 (ms) | 0.252827 | — |
| render+swap P95 (ms) | 0.265748 | — |
| render+swap P99 (ms) | 0.453971 | — |
| rAF 间隔 P50 (ms) | — | 16.699999999999818 |
| rAF 间隔 P95 (ms) | — | 16.700000000000728 |
| rAF 间隔 P99 (ms) | — | 16.80000000000109 |
| 实测 FPS | — (vsync=0 无上限) | 60.00360021601296 |

> 原生 render+swap = GL 提交+swapbuffers（vsync=0，不含 CPU 求值 advance/prepare_frame）；WebGL rAF 间隔 = requestAnimationFrame 间隔（含浏览器合成+vsync）。
> 两者语义不同。原生 CPU 求值基线见 docs/validation/p7-performance-baseline.json（azuki 425us/帧、fraise 768us/帧）。
> 原生无 vsync 时理论 FPS 上限 ≈ 1000 / (render+swap + cpu_eval)；真实壁纸场景受 vsync 限制为 60 FPS。

## 7. 局限性

- 原生 CPU 提交时间与 WebGL rAF 间隔语义不同，不能直接比较绝对值。
- WebGL 在 headless chromium 运行，`--use-angle=gl` 尽量硬件 GL，但仍可能与桌面浏览器有差异。
- 采样间隔 100ms，短时尖峰被平滑；P95/P99 反映采样粒度内尾部分布。
- 串行测量避免 GPU 干扰，但两次运行间系统状态有微小漂移。
- 仅单模型，不同复杂度下比例可能不同。
