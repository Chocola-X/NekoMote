# 2026-11-18 低端机性能复核

基线 `c259af1`，历史对照 `v0.5.4`（`4fbf55a`）。复核了
`experiments/NekoMote_Performance_Report.md` 的 A–Q。仅保留**重复使用网格列比例**：
14 个实机工况中会话 CPU P50 均有改善，最终补丁平均 −3.86%，几何构帧 P50 平均
−5.51%。曲面链展平、GL 缓冲孤儿化和 Vulkan 顶点 staging 均只在隔离副本试验，未合入。

## 实机基线

测试机为 i5-2410M（2 核 4 线程）、4 GB、Intel HD Graphics 3000、Debian 12。
原生 Xorg / KWin X11，Mesa 22.3.6 直接加速 OpenGL 3.3，保留现有 schedutil；
Xorg 有 1920×1080 / 60 Hz 虚拟输出，未接物理显示器。Debian 12 隔离构建使用
GCC 12.2、Release/O3/LTO、`-march=x86-64 -mtune=generic`，产物上传后核对 SHA256。
最终播放器的 ELF 标记为 `x86-64-baseline`；另在 AlmaLinux 8.10 / GCC Toolset 13
构建通过运行时目标，没有重跑整套发行流程。

CPU 探针固定逻辑核 2、seed 12345、1/60 s；每次预热 120 帧、采样 600 帧，七款模型
各测待机和周期拖动/视线，三轮交错。各工况取三轮对应分位数的中位数，再对相对变化
等权平均。GL 播放器采用 seed 1、静音、fit、平色背景，配置 1920×1080 / 60 FPS，
窗口实际 framebuffer 为 1920×1007；三款、三轮、每次预热 120 帧采样 600 帧。
不注入系统输入；未将截图、profiler 或构建计入耗时。主机独立记录
player / Xorg / KWin 进程 CPU 和 player RSS，不能用这些值代替整机 CPU 或表面实际扫描输出。
CPU 提交耗时可包含驱动等待，不是 GPU 执行时间。

| 历史对照：v0.5.4 → c259af1 | 结果 |
| --- | ---: |
| 会话 advance + prepare P50 / P95 / P99 | −25.62% / −25.08% / −24.79% |
| 独立几何构帧 P50 | −18.60% |
| GL 播放器进程 CPU，相对变化 | −10.72%（三款均下降） |
| CPU 提交 P95 | −17.10% |
| 实际播放循环 | 两版均约 59 FPS |
| 播放器 RSS | 均约 79–80 MiB |

历史版与当前版用于评估已有进展。七个待机工况帧指纹相同，七个拖动/视线工况的
指纹不同；历史对照也只有 2/6 对固定步 PNG 字节相同。未把历史版对照当成语义认证，
也不把差异归因给某个提交。候选正确性以
`c259af1` 为准。独立 perf 抽样（wintermaid，418 个用户态 cycles 样本）显示
曲面多项式约占 31.6%，节点求值约 24.3%，GL prepare 约 5.3%；这是采样归因，
不能把整个求值函数的占比归给其中某个循环。

## 逐项结论

| 建议 | 核查结果和取舍 |
| --- | --- |
| A / B / F：分支标注、组合祖先、深度排序 | 关键帧已有区间游标；组合的终点随活动姿态变化，且要保留逐祖先的加法次序。深度/活动节点会变，缓存还需检查失效。未证实三者是瓶颈，跳过。 |
| C：AVX2；K：BC3/BC7/ETC2 | 暂不推进。保留 x86-64 v1 和无损图集。ETC2/EAC 也有损，且不是桌面 GL 3.3 的通用能力，见 [Khronos 扩展说明](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_ES3_compatibility.txt)。 |
| D：展平曲面链 | 当前已跳过刚性节点。逐图元把实际曲面链搬到预留的连续指针区，顺序和算术完全不变；三轮会话 P50 **+0.26%**、构帧 P50 **+0.34%**，撤回。只变形四角再插值会改变曲面内部点，不是等价优化。 |
| E：网格插值 | 保留等价的标量实现。每列直接做一次 double 除法，各行复用；UV 复用同样的行列比例，仍在原位置保存 Float32。没有改曲面公式、纹理或合成。 |
| G：持久加载线程 | 现有异步加载仅在角色切换时发起。没有证据显示线程构造影响加载延迟或稳态 CPU，跳过。 |
| H：GL 上传 | 持久映射需要 [ARB_buffer_storage](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_buffer_storage.txt) 或对应更高版本能力；实机未暴露该扩展。GL 3.3 兼容的顶点缓冲 orphaning 实测两款 CPU **+2.68% / +1.81%**，P95 提交耗时也上升，撤回。已按版本复用的 EBO 不参与候选改动。 |
| I / N：纹理哈希 / 合并图集 | 扫描本地 195 份 `model.nkm`：189 个一张、5 个两张、1 个三张。桌面 GL 的 RECTANGLE 只是采样目标；素材本身已图集化，加载时已有无损裁切。当前数量下跳过两项。 |
| J：GL 状态缓存 | 纹理绑定与遮罩 scratch 已有局部缓存，壳可更改 GL 状态。未看到足够归因来扩大缓存范围；如果重测，只试单次 render 内减少重复调用。 |
| L：Vulkan 设备本地缓冲 | 可在 Vulkan 1.0 做，但带宽比不是整帧收益。隔离试验只迁移动态 VBO，EBO 保持已验证的索引复用。完成 P50 平均 −3.92%，两组变慢；一组完成 P95 +8.05%，且新增一份顶点缓冲与 copy/barrier，撤回。 |
| M：Vulkan 命令复用 | producer/revision 早退的是 prepare（校验/上传），不是宿主命令录制。活动帧的遮罩、状态、目标和命令有变化；无录制瓶颈证据，跳过。 |
| O / P：中间图像、VMA | GL/Vulkan 中间目标同尺寸复用，resize 才重建；遮罩容量单独计算。当前少量图集和缓冲不支持接近分配上限的推断，暂无证据引进 VMA。 |
| Q：音频流式 | 全量解码只在启用声音的模型加载时发生；按实际 session 引用和 FLAC STREAMINFO 计算，Float32 PCM 组中位 5.78 MiB、最大 6.29 MiB，最长 5.72 秒。当前没有长音频的前提。若后续要继续降声音内存，先对比保留源 16-bit PCM 的实机内存、音量/口型和触发延迟。 |

Vulkan 试验仅在本机 Xeon E5-1680 v4 / RTX 3080 Ti、NVIDIA 580.82.09 执行，
GCC 15.2 Release/LTO，1280×720、3 模型 × 待机/拖动、120 帧预热、600 帧 × 三轮交错。
用既有 Vulkan probe 测量到 fence 完成的端到端延迟（不是单独的传输计时），
18 对样本结束后的 PNG 字节相同。没有将试验扩展到 UMA、可映射设备本地内存策略，
或改变宿主提交/同步契约。

## 最终补丁验收

| CPU 指标 | c259af1 → 最终补丁 |
| --- | ---: |
| 会话均值 / P50 / P95 / P99 | −3.84% / −3.86% / −3.64% / −3.66% |
| 几何构帧 P50 / P95 / P99 | −5.51% / −4.79% / −5.07% |
| 会话 P50 单工况范围 | −4.97% 至 −3.03% |

14 个工况每次 600 帧的几何/绘制协议指纹均与当前基线相同；所测的会话、几何稳态
普通 C++ 堆分配仍为零。列比例放在约 2 KiB 的栈数组中，无新增实例常驻内存或 GPU
对象。边界测试覆盖 256 份细分集中在单轴的最大列，以及插值时计算出的自动细分超限后
拒绝构帧。本机 262 个 CPU 测试用例通过、1 个缺外部源素材的用例跳过；OpenGL、GLES、
Vulkan 三套 GPU 回归均通过。低端机的 6 对 OpenGL 固定步 PNG 与当前基线逐字节相同。

最终两款 GL 工况按相同方法各交错三轮，每次采样 360 帧：

| 模型 | 播放器 CPU（单逻辑核 100%） | CPU 提交 P95 | 播放循环 |
| --- | ---: | ---: | ---: |
| chocola/date-a | 25.96% → 26.03% | 4.012 → 3.973 ms | 58.993 → 58.982 FPS |
| chocola/wintermaid | 18.54% → 18.14% | 4.702 → 4.636 ms | 59.297 → 59.300 FPS |

两款播放器 RSS 都约 79 MiB。收益集中在 CPU 求值，当前端到端样本不支持宣称
整个桌面 CPU 或帧率获得同样幅度的改善。

独立的 date-a PMU 采样中，6 秒短样本的封装功率约 8.88 → 9.05 W；交换顺序并延长到
每版 2×12 秒后，封装约 8.91 → 8.83 W，内显域约 3.18 → 3.16 W，Render busy
约 86.4% → 87.6%。封装差值反向，不能据此宣称功耗改善或回退。RAPL 读的是 CPU
封装和内显域，不是插座功率；两项不能相加。

原始数据、测试入口和未采用的补丁保留在
`experiments/performance-review-2026-11-18/{work,evidence}/`。固定步截图与功耗采样
独立于 CPU 和播放器的计时。单次短场景不用于长期稳定性、真实屏幕、多物理输出或显存认证。
