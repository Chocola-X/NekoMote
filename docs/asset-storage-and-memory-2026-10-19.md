# PNG、音频与模型存储优化

基线为用户回滚后的 `5a9b4e2`（0.5.2）。图片继续使用 PNG；本轮交付 FLAC
语音共享、压缩二进制模型和背景渐变后的纹理回收。完整测量记录见
[结构化证据](validation/asset-storage-memory-2026-10-19.json)。

| 195 份模型 | 362.78 | 13.58 |
| 角色音频 | 549.07 | 18.84 |

## PNG 按行解码能降低多少内存

回滚版本已经用 libpng 实现非交错 PNG 的两遍逐行裁切：第一遍只保留一行并计算
精确非零 RGBA 边界，第二遍将需要的行写入裁切缓冲。324 张现有 PNG 全部非交错；
不再有额外的完整原图临时缓冲。Adam7 输入仍需要完整图像合并各扫描 pass。

Chocola date-a 的 4096×2048 图集在独立进程中的结果：

| 路径 | 解码像素缓冲 | 持有时 RSS | 释放像素后 RSS | 单次加载 |
| --- | ---: | ---: | ---: | ---: |
| 完整解码 | 32.00 MiB | 35.98 MiB | 4.29 MiB | 92 ms |
| 现有逐行裁切到 4096×1577 | 24.64 MiB | 28.60 MiB | 4.27 MiB | 178 ms |

这是现有两种加载路径的对照，不是本轮新实现的提速。裁切多解码一次，降低 CPU
像素缓冲和 GPU 图集容量，加载耗时更高。最终像素使用 mmap 所有权，上传后 munmap，
不会作为大块空闲堆长期留在分配器中。

继续将 PNG 按行直接上传 GPU，可以进一步省掉这份约 25 MiB 的 CPU 加载缓冲，
但不会降低上传完成后的 RGBA8 显存或稳态 CPU 内存。当前候选由后台线程解码、图形
线程上传；逐行上传须改变交接机制，按条带合并上传以免产生数千次驱动调用，并分别
处理 GL、Vulkan staging 与 Adam7。当前保留已验证的逐行裁切和像素及时释放，未将
图形调用移入 asset_io 或加载线程。

## 二进制模型与运行开销

只换二进制编码不足以得到 ZIP 的压缩率：Python MessagePack 对照为 273.87 MiB，
压缩 JSON 为 21.33 MiB，压缩 MessagePack 为 14.33 MiB。正式编码器可精确使用
Float32，实际 MessagePack + DEFLATE 容器进一步降至 13.58 MiB。

新文件名 `model.nkm`，头为 `NKMMPK01` 和 uint64 小端的解压长度，后接单个 zlib
流。复用 PNG 已依赖的系统 zlib；没有新加压缩框架。libFLAC 默认固定 1.4.3 静态
链接，系统依赖模式显式要求 flac≥1.4。编码、WAV 和来源 JSON 转换留在离线 importer。

运行时有 32 KiB 压缩输入和 32 KiB 输出缓冲，加 zlib 窗口，按 frame/layer/part 转为
强类型对象后立即丢弃该记录 DOM；没有完整解压文件或完整模型 DOM 的常驻副本。
检查容器版本、512 MiB 解压上限、编码大小、精确长度、zlib 校验、截断、尾随数据、
重复键和 256 层嵌套限制。旧 JSON 仅通过显式迁移工具读取。

同条件独立加载微基准（每个进程加载 4 次，第一遍预热，后三次中位数）：

| 模型 | 原 JSON | 新模型 | 原/新最终 RSS KiB |
| --- | ---: | ---: | ---: |
| chocola/date-a | 71.3 ms | 54.4 ms | 13392 / 13392 |
| coconut/casual | 78.8 ms | 52.3 ms | 13452 / 13444 |
| fraise/maid-a | 107.8 ms | 79.6 ms | 14336 / 14336 |

含模型编译、PNG 和音频的候选加载，裁切像素及 PCM 大小完全一致。释放像素后的
RSS 约 15–17 MiB；峰值约 40–46 MiB，新旧差异小于 0.3 MiB，不宣称有稳态 RAM
收益。FLAC 只在加载时解码，声音设备继续使用同样的 PCM，后续播放不引入解压工作。
本轮没有改变逐帧模型求值、动画或绘制公式，以上耗时不代表稳态帧时间或功耗。

## 背景旧纹理驻留修复

原实现渐变后只画新背景，但专用 renderer 仍持有旧、新两张纹理。GL/Vulkan 新增
显式 `release_unused_textures()`：成功 prepare 后、render 前释放没有普通或遮罩命令
引用的纹理，保留当前绘制内容。Vulkan 同时回收描述符，沿用宿主已完成上一轮 GPU
工作的生命周期契约，没有新增 wait/finish、重上传或应用业务状态机。

真实 Chocola、800×1080 输出、BG_07A/BG_13A（各 1920×1080 RGBA8）隐藏窗口检查：
初态 1 张背景；渐变中 2 张；中断渐变后最终仍回到 1 张；多次切换每次稳定后都是
1 张；清除后 0 张；销毁壁纸后全部纹理为 0。每次稳定释放 7.91 MiB 旧纹理容量。
这是逻辑 GPU 存储量，不冒充 NVIDIA 进程显存或 RSS 恰好下降相同数值。

合成 GL/GLES/Vulkan 测试验证渐变画面不变、mask-only 引用保留、失败 prepare 不破坏
旧帧、12 轮纹理槽与描述符复用；预热后 120 次稳态回收调用无 C++ 堆分配。
