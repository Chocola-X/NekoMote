# 2026-11-08 菜单展开位置及高度修复

基线：`46a228f`。任务来源：用户反馈控制菜单展开较多条目时跳到最左侧，
要求修复并将展开总高度限制为壁纸输出高度的五分之四。

## 原因与修改

共享 UI 的 `validate_sidebar_position` 原先用整个菜单矩形校验保存位置。
展开列表改变高度后，底部越界会同时清除 `is_free` 并把 x、y 都重置为 8，
随后进入默认左侧滑入布局。这与模型、桌面插件或渲染后端无关。

现在底部越界只上移菜单，保留横向位置和自由放置状态；真正无效的坐标
（非有限值、负值、横向越界或起点已落在输出下方）仍采用原来的默认位置恢复。
本次替代了旧位置持久化报告中“完整矩形越界就恢复默认”的底部处理规则。

`build_sidebar` 将包含标题的菜单总高度限制为输出高度的 80%，长内容继续使用原有
裁剪和滚动逻辑。点击范围同步限制到可见内容，避免菜单下方隐藏条目响应。
输出变小时重新计算上限，收起内容时限制滚动偏移。
极小输出不再以 64 像素最小高度突破上限；内容区域为零时只裁剪绘制标题，
短内容区的滚动条也不会长于自身区域。修改集中在共享 `ui`，player 和各宿主共用。

## 验证与范围

- Release/LTO/Werror 全目标构建、格式及 diff 检查通过。
- 菜单与布局 19 个测试、325 个断言通过。其中新增 5 个回归用例：真实菜单点击展开/
  收起后的横向位置、1080/720/480/80/55/32/0 高度上限、滚动到底部及收起后的偏移、
  保存位置只有底部越界时保持自由放置、隐藏内容点击无效而滚动进入后可点击。
  原有无效坐标恢复测试保留，底部负例改为起点越界。
- 非 GPU CTest 261 个入口：259 执行通过、2 跳过（缺原模型 JSON、缺 CJK 字体）；
  GL、GLES、Vulkan 和 Python ABI 图像共 4 个 GPU 入口通过。
- 验证沿用隔离 Xvfb `:88` 和 Mesa 软件驱动，未安装插件或修改用户桌面；
  真实桌面的主观交互尚未复测。

CPU 布局微基准使用 Xeon E5-1680 v4 / GCC 15.2.1 / Release LTO，800×1080 输出、
195 个合成条目、不提供字体且 Painter 仅计数；每场景预热 2000 次，100 组各 1000 次，
旧版与修复版交替执行 3 轮。两版测量区间内均为 0 次 C++ 堆分配。
三轮 P50 中位数：收起 0.064 → 0.060 微秒，展开 1.169 → 1.602 微秒。
展开场景增加约 0.43 微秒，包含新增的可见区域命中检查。
这是正确性修复，未宣称性能收益；该局部测量不含 GPU、字形、设备线程、实际呈现或功耗。
原始 P50/P95/P99、微基准源码和测试日志见 [验证目录](validation/sidebar-layout-2026-11-08/)。
