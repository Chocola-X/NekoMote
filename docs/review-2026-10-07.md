### R3：C ABI 失败被吞掉、布局和长度边界不成立（阻断真实宿主接入）

- 位置：`src/abi/abi.cpp:43`、`:542–640`，`include/nekomote/abi.h`。
- reserve/upload/prepare/resize/render 为 `void`，`catch (...) {}` 无错误输出；初始化/加载返回 NULL 后也丢失字段来源。宿主无法区分正常画面和失败，甚至可能继续使用上一帧。
- 对 C / C++ 顶点和命令直接双向 `reinterpret_cast`，依赖 C++ `std::array`、强类型 ID、枚举的对象布局及类型别名关系，违反公共 ABI 契约。没有字段转换或 layout 证据；只读几个字段再 `(void)` 不是布局验证。
- upload 在验证 width/height 前计算指针区间，且没有 pixel byte count；prepare没有建立可靠的指针/计数、枚举和索引边界。播放状态999实际返回 `NEKOMOTE_OK`。
- 修复要求：有名错误码、来源诊断、明确失败输出；边界处使用真正共享的 C 值类型或预分配逐字段转换，不以尺寸相同证明类型可互换；检查长度与整数溢出；定义程序必须活过实例、借用字符串/帧寿命和图形上下文责任。

### R4：ABI 初始化失败泄漏，标准 ASan 没有覆盖此路径

- 位置：`src/abi/abi.cpp:302`、`:526`。
- 先 `new` wrapper，再构造可能抛出的内部对象；后者失败时 wrapper 没有 RAII 所有者。
- 传入合法 loader 函数、使所有 GL 查询返回 NULL：renderer返回NULL，LeakSanitizer报告 **8 bytes / 1 allocation**，栈指向`:526`。临时诊断无窗口，不涉及驱动分配噪声。
- 修复要求：部分初始化全过程使用 RAII；失败/销毁/借用寿命单测进入无需显示服务器的 ABI 测试目标，不能继续只依赖真实模型及图形构建。

### R5：C 宿主复制声音服务，仍有阻塞与线程风险

- 位置：`apps/abi_host/main.c:164`、`:264`、`:330`。
- pa_simple_get_latency仍在mutex内部调用；主线程audio_rms/audio_submit取同一把锁，之前“所有阻塞调用均移出锁”的结论不成立。
- 普通int `quitting` 被主/worker无同步读写；停止及析构使用drain、join，不能保证停止立即丢弃旧声音或有界退出。Pause只停止继续写入，已排队PCM仍可发声。满队列和Pulse失败也没有反馈错误。
- 该文件重写WAVE解码、RMS和Pulse服务，和已存在的asset_io/audio有双套实现；角色holder浅拷贝包含pthread对象，补丁停止旧线程并不能建立清晰所有权。
- 修复要求：C验证宿主保持薄层；通过明确设备服务边界复用现有PCM/异步audio实现。共享设备功能需要契约测试，不能把此宿主移植成Plasma正式应用。

### R6：背景时钟、能力查询与切换事务缺口

- 位置：`src/application/session.cpp:127`、`:639`；`apps/player/main.cpp:830`。
- 实际序列：set_background(100) → fade_background(101,1s) → pause → advance(.25)，目标alpha从0变.25。advance(100)让背景直接结束，而模型最多追赶15作者步，两者恢复策略不一致。
- `touch_available()` 只看前两个zone，忽略其余zone和区域定义；将全部region移除后仍报告true。应覆盖所有实际可用区域与反应。
- 角色切换先移走当前holder/停止声音，再加载候选。候选缺失/不支持时异常退出播放器，旧会话不能继续；暂停状态还被清除。reset清除背景但holder仍保留has_background，恢复行为没有共同契约。
- 修复要求：暂停/恢复、重入渐变、候选加载失败和背景/reset语义先形成共同application/宿主契约，再补数值/画面回归。
