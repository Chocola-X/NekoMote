# 性能优化试验与回退经验汇总

本文件持续维护，不按每次试验拆分文档。优化前先查阅相关条目；遇到正确性失败、
性能倒退或有条件的收益，更新本文件并链接实际证据。日期、提交与测量范围要明确，
不能把某台机器的结果写成跨平台定律。用户允许整体收益成立时接受局部轻微退步，
这不等于允许画面或行为正确性下降。

## GLES 裁切图集直接使用 NPOT：已撤回

- 条件：将 GLES 的 POT 存储直接改成裁切后的 NPOT 尺寸，仍使用归一化 UV 与线性过滤。
- 结果：2026-11-08，3 型号、3 时刻和 3 种视图的 27 对图像均有差异。
  两图 alpha 均至少 16/255 的像素仍有 6～16/255 的最大通道误差。
- 原因：GLES 支持 NPOT 只证明格式可用，不证明除法、采样和遮罩放大后仍等价。
  POT 的二进制缩放是现有精度约束的一部分，不能只按规范支持情况删除。
- 处置：恢复 POT；如重试，先证明新的采样表示满足冻结画面门槛，不能重生成 golden。
- 证据：[前轮报告](remaining-optimization-2026-11-08.md#4-gles-npot撤回)、
  [撤回补丁](validation/remaining-optimization-2026-11-08/rejected-npot.patch)。

## 曲面重排与降精度：不能用代数等价替代输出验证

- 原算法的两个坐标共需 48 次乘法、32 次加法；逐点两趟算法为 40 次乘法、40 次加法。
  “48→20”遗漏了双坐标，并不能推出几何耗时降低 60%～70%。大幅节省需跨顶点复用。
- 2026-11-08 隔离单级对照：414,477 次真实调用中，重排产生 30 次 Float32 差异，
  最大坐标差约 7.63e-6 模型单位；未把候选结果继续传到后级，所以不代表完整链画面已验证。
- UV 的 Float32 保存、旋转域和前级曲面改变了后级输入；不能按原始网格行列缓存权重。
  抽样中满足所检查双轴共享条件的调用，待机约 89%，拖动/视线约 0.66%。
- 当前编译器已经部分向量化。保留累加顺序的 x/y SSE2 候选，三轮总 P50 仅约 -0.62%，
  未作为确定可观收益合入。该结果不代表其他 SIMD 方案都无效。
- `float` 的相对精度不能直接当绝对像素精度；域逆矩阵、抵消、嵌套和遮罩需分别验证。
- 证据：[曲面优化审查](compound-review-audit-2026-11-08.md#5-高风险求值优化建议)。
  上述细分试验记录在本地被忽略的 `experiments/evaluator-analysis-2026-11-08/`，
  不视作可在缺少该目录时独立复现的已提交认证。

## 热结构变大可能抵消局部计算收益

- 2026-11-08，直接将每个 State 的控制点扩大为 double，build P50 改善约 6.25%，
  节点 evaluate P50 增加约 3.35%，会话总 P50 只改善约 2.13%。
- 最终改为实例固定数组，State 只借用地址，降低逐节点清零和遍历成本。
  会话总 P50 改善约 5.59%。仍记录新增常驻内存，不把减少计算说成免费。
- 证据：[控制点预处理](compound-review-audit-2026-11-08.md#3-控制点预处理)。

## 物理前后求值不能直接合并

- 物理前读取动画参数对应的锚点；物理后应用输出参数并生成最终几何，两者输入不同。
  拖拽时还临时切换物理原点。删掉其中一次会改变反馈和交互行为。
- 按需定位器求值是另一项有效候选，但必须包含祖先、组合曲面、排除附件和分支依赖，
  并保持错误传播与失败事务；不能只计算定位器的局部平移旋转，也不能复用上一帧锚点。
- 证据：`src/runtime/playback.cpp` 的 `step_tick` / `prepare_frame`，
  [物理契约](../include/nekomote/runtime/physics.hpp)。报告的百分比仍需独立基准证实。
- 2026-11-10 已实施定位器范围求值：世界变换/曲面准备仅覆盖全部导出定位器的祖先，
  但每遍仍扫描所有选中姿态并计算组合状态、传播原有错误。不能把无关节点整体 `continue`
  提前到参数/组合校验之前，否则可能静默接受原来应拒绝的分支。
- 最初将所有 combine 也放进世界闭包，覆盖平均77.51%节点；实际组合校验所需的是
  跳过前已计算的 transform/child_sync/祖先pose，世界坐标不参与。独立复核后只保留
  locator祖先，覆盖平均14.96%。这个缩减依赖当前跳过点位置，后续挪动代码必须重审。
- 部分模式不能构帧或任意观察未求值节点；下一次完整模式需重建全部状态。连续组合、
  排除附件、失活分支、错误恢复和多会话切换分别有证据，不能用单个静止截图放行。
  本轮实现、实测收益和覆盖边界见[报告](anchor-evaluation-2026-11-10.md)。

## LTO 内联变化可能拖慢未改算法的热循环

- 2026-11-10 按需锚点首版：advance P50 -30.05%，但 build P50 +13.25%、prepare
  P50 +5.78%，Session 总 P50 仅 -1.34%，局部总 P50 最差 +1.94%。
- 重编原版复查仍复现原成本。反汇编发现原版将曲面多项式独立调用，候选把它内联进
  顶点循环；build_frame 机器码由6506增至7297字节。没有据此宣称所有内联都慢，
  或仅凭代码大小断言寄存器/缓存的具体贡献。
- 保留共享公式，通过局部 `[[gnu::noinline]]` 包装固定 prepared-patch 调用边界，
  将函数体降至6678字节，再完整复查动态/图像并重测整体。数学表达式、累加与保存顺序
  不动，不全局降低优化等级。该处性能约束有本机证据，不保证所有编译器/平台都获益。
- 最终14组总均值/P50分别-8.24%/-8.77%，prepare P50 -3.52%；独立build P50仍+1.18%，
  单组总P99最差+6.61%。按整体收益接受这一局部代价，未把首版和最终结果混用。
- 后续即使只优化锚点，也必须同时测 prepare/build，不能假定未编辑的算法耗时不变。
  初始三轮数据、最终数据和边界补丁见[本轮证据](validation/anchor-evaluation-2026-11-10/README.md)。

## 接受局部退步时明确成本与覆盖范围

- 曲面祖先链缓存：2026-11-08，7 型号 × 2 输入三轮总 P50 -7.60%，
  独立 evaluate P50 +0.20%，总 P99 平均 +3.87%；每实例约增加 3～4 KiB。
  结合总均值/P50/P95 收益保留，不声称所有分位数改善。
- 索引复用：Vulkan prepare CPU 减少不代表 GPU 完成延迟稳定改善。
  同样不能把 runtime、renderer 的百分比相加为整个桌面的收益。
- 证据：[祖先链报告](curve-chain-optimization-2026-11-08.md)、
  [索引复用报告](compound-review-audit-2026-11-08.md#4-索引复用)。

## 最终合成 scissor：2026-11-09 候选已撤回

- 候选：在必需的顶点有限性检查中累计所有顶点的保守 bounds（包含 mask source 与未引用点），
  只对最终 ProtectedStraight 合成设置 scissor，沿用两像素边界与翻转规则；完整 clear 不裁剪。
- 4K、3 真实型号 × 待机/拖动、三轮交替、每组 120 帧预热/300 样本：
  GL 完成耗时均值 +3.17%、P50 +4.51%；Vulkan 均值 +2.87%、P50 +4.99%；
  GLES 均值 -0.58%、P50 -0.58%，三种 API 的 prepare 均增加约 8%～10%。
- 18 对最终图像逐字节一致，新增分数坐标/翻转/屏外/空帧 clear/preserve GPU 检查通过，
  但没有证明综合收益，因此撤回候选及专项测试。不要将这次结果推广为任何 scissor 都无效。
- 全屏透明片元原 shader 已 discard；顶点包围盒不等于非透明像素占用，保守 bounds 又含
  遮罩源。省片元的潜力未必抵得过 CPU 统计与状态成本；不能按角色可见面积估算省时比例。
- 后续如重试，先计量实际裁剪面积与 GPU 时间，再比较更紧的 bounds 提供方式及其 CPU 成本。
- 证据：[本轮审查](optimization-audit-2026-11-09.md)、
  [撤回补丁](validation/optimization-2026-11-09/rejected-scissor.patch)。

## 利用编译不变量复用验证结果，避免引入无谓缓存

- 2026-11-09 检查祖先验证时，发现编译器已把 `has_sprites` 传播到全部祖先，求值又按
  祖先先于后代执行、失活父节点跳过后代。因此每个活动绘制节点只需检查自身；原有
  全祖先回溯的错误会在同一 pass 更早的位置被检测，错误来源不变。
- 没有新增 unsupported 传播数组，也没有关闭检查。无 sprite 的定位器可能未走此分支，
  所以其 `sample_locator` 祖先验证必须保留。这一结论依赖上述编译和遍历不变量。
- 相对关键帧缓存版，三轮 14 组总 P50 -10.39%，独立 evaluate P50 -24.13%；帧数据一致。
  反观关键帧区间缓存，总 P50 只有 -0.41%，说明报告强调的二分查找未必是主要成本。
- 证据：[本轮审查](optimization-audit-2026-11-09.md#阶段三消除求值中的祖先重复验证)。

## C++20 语言选项不能替代旧标准库验证

- 2026-11-10，锚点优化的新增逐位比较在GCC15通过，但 `std::bit_cast` 不存在于
  Ubuntu20/GCC10标准库，导致native20、Plasma5、X11的两个架构共六个job编译失败。
  新审计工具也包含相同用法，必须一并核查；不能只修日志中的首个测试断点。
- 测试对每个float使用 `memcmp`，工具用带尺寸断言的 `memcpy` 生成32位指纹字。
  保留正负零和全部位模式，不弱化为 `==` 或容差，不添加两套编译器分支。
- 后续新增测试和开发工具也应按最低基线验证；Debian12或本机新GCC通过不等于
  GCC10标准库支持。修复前后用真实GCC10重现/验证，记录实际sysroot和架构边界，
  不把临时宿主库链接测试说成完整发行包认证。
- 证据与范围见[CI说明](github-actions.md#2026-11-10锚点测试的-gcc10-标准库补修)。

## Qt 帧通知、暂停 dirty 与宿主刷新率

- 2026-11-10，复核 Wayland CPU 报告：Qt FBO 的 `renderPending` 决定是否调用
  项目 renderer。不能按显示器 Hz 推定项目每帧求值次数，或停掉 timer 后假设动画
  会自动继续。不限帧的0ms timer 确实会在两次提交间忙轮询，改用明确的续帧通知。
- 初版对所有模式连接排队 `frameSwapped`。首轮 XWayland/desktop GL 的60 FPS
  进程 CPU 均值出现约+6.3%局部回退（短预热样本），即使不限帧的整体收益很大，
  有限帧也不需要这条通知。最终仅在不限帧时连接、切回有限帧时断开，再充分预热重测。
  这不是对 Qt 排队信号普遍有害的结论。
- `needs_render` 只表达 presentation dirty，正常动画 advance 不保证置脏；单独检查
  会冻结动画。必须保留实际 paused 条件，并在 advance/poll/输入之后判断。新 FBO
  要独立强制绘制，不能靠尺寸或 GL 名称判断是否已有内容。Vulkan 还必须在开启新
  recording 前判断，并保留可能释放上一帧资源之前的等待。
- 暂停的 `initialized_time` 可以长期为 false；每个 callback 都 set_paused 会反复
  置脏，使复用失效。只在播放同步边界更新，同时在重载模型时重新同步一次。
- 审计中的暂停 resize 图像比较最初包含了会被正常 clamp 的图标，重载检查又用
  固定150ms推定 GPU 加载完成。最终分别按原布局语义比较，并等待实际重载绘制完成
  后再采样空闲，不能放宽像素门槛或把加载帧计为稳态重绘。
- 该收益依赖帧率/暂停/额外 update 条件，既有默认暂停本就停 timer；不能声称所有
  暂停都有新收益，或把独立 Qt 宿主 CPU 的百分比当成整个 plasmashell/桌面的收益。
  复核、原始数据和未通过的既有诊断子例见
  [本轮报告](wayland-cpu-audit-2026-11-10.md)。

## 测量与实施约束

- 2026-11-10真实180 Hz桌面：有限FPS的timer之外，逐鼠标事件`update()`仍会绕过限制，
  自然鼠标活动时60 FPS配置可达到约86～125次实际绘制/秒。将输入排队交给下一次有限帧
  消费后，必须同步检查事件容量；原32项不足以支撑高轮询率。保留完整按下/移动/释放顺序，
  不把任意Move合并为最后位置，否则往返移动可能丢失拖动阈值与短点击语义。
- Qt窗口提交与项目FBO绘制必须分开计数：无模型最小程序在本机basic循环下约59/118，
  threaded约59/59。虚拟60 Hz结果无法排除真实高刷宿主额外提交，不能将全部进程CPU
  差额归给模型，也不能在插件中强改整个plasmashell的渲染模式。已知缺陷和复现见
  [真实桌面报告](wayland-desktop-cpu-2026-11-10.md)。
- 扩大有界队列时避免连带全量复制：GUI成员数组仅在Qt阻塞GUI的synchronize内借用，
  renderer只复制有效范围后清队列；借用不跨帧。计数诊断默认关闭，其逐swap回调有成本，
  开启诊断的Plasma CPU不能直接与无诊断的layer-shell归因比较。
- 重载停滞在恢复原Actions安装后也曾出现；保留为来源未定的生命周期问题，不能仅凭
  一次重启正常或切换后端恢复就宣布修复，也不能直接写成Plasma自身缺陷。
- 先冻结基线二进制与资产/源代码哈希，再修改代码；基准不要与构建、测试或其他采样并行。
  插桩计数与耗时采样分开；交替顺序并保存均值/P50/P95/P99 和局部不利样本。
- ASan 与 Release 使用独立的依赖构建目录，可以共享只读依赖源码；共享 `_deps/*-build`
  曾污染 Release 依赖对象。sanitizer 耗时不能进入发布态性能比较。
- UI 透明图元保持绘制次序，按材质全局重排会改变叠加；批处理要保留相邻兼容状态和剪裁。
- 图形 API 的能力支持不等于画面等价或实际更快；截图与读回只用于诊断，不混入帧计时。
